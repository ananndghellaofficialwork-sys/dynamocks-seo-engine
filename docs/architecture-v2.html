Dynamocks SEO Engine — Architecture v2

Manual-first pipeline for a live 472-product store. The agent earns autonomy; it is never granted.

Guardrails

  • • Undo written before every write, at every level
  • • Staleness guard: abort if the store changed since generation
  • • Semantic uniqueness gate vs all live copy + batch siblings
  • • Eval score vs 49 human-approved gold outputs
  • • Max 10 products per run — a permanent ceiling
  • • One retry on collision, then it asks for a human

Decisions & rejected alternatives

  • • SQLite over Postgres — 472 rows, one file, transactional
  • • Embeddings over a vector DB — brute-force cosine is sub-ms here; a vector store earns its place at ~50k docs
  • • CSV review over a web UI — meet the reviewer where she works
  • • GraphQL productUpdate(product:) — the input: form is deprecated, verified against the live schema
  • • seo.title first — null on ~99%, so nothing good can be destroyed

Why manual first

  • • This is a live business, not a sandbox
  • • 49 listings improved by hand became the evaluation baseline — the hardest asset in any eval, produced as a by-product
  • • Every module except agent.py is used at L0 and unchanged at L2
  • • Promotion criteria were written before the agent existed — criteria written after are rationalisations
